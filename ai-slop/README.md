# AI Slop 커밋 검사

Conduit에서 AI가 게시글 작성을 수정한 뒤 커밋하는 시연용이다. 새로 추가한 프론트엔드 디버그 흔적을 찾고 스테이징한 백엔드 코드로 글 생성 조건을 실행한다. 파일 위치, 실패한 조건과 미확인 범위를 코파일럿에 다시 전달할 수 있다.

## 수정한 기능 바로 확인하기

Conduit 작업 폴더에서 아래처럼 질문한다. 첫 두 줄은 터미널 세션에서 한 번만 설정한다.

```sh
SLOP_DIR=/absolute/path/to/my-copilot/ai-slop
alias slop='python3 "$SLOP_DIR/gate.py"'
slop "제목이 공백뿐이면 이제 등록이 막혀?"
```

질문으로 실행하면 Git이 추적 중인 프론트와 백엔드 파일의 현재 내용을 확인한다. 실패하면 첫 화면에서 근거와 채팅에 붙여넣을 수정 요청을 볼 수 있다. 수정 후 같은 질문을 다시 실행한다. 새로 만든 파일은 한 번 stage해야 포함된다. 커밋할 때는 실제 stage한 코드로 다시 검사한다.

## 모델이 확인하는 과정

1. 사용자 요청과 staged 소스의 변경 내용을 모델에 전달한다. 모델이 놓쳤을 법한 조건을 설명하고 그 조건을 확인할 도구를 고른다.
2. Python이 선택한 도구를 실행한다. 두 번째 모델 호출은 관찰된 결과를 받아 수정 의견을 작성한다. 첫 화면에는 관찰한 동작과 수정 요청을 보여준다. 가설, 선택한 도구와 전체 관찰값은 `--json`에 담긴다.
3. 커밋 훅은 같은 tree에서 필수 검사도 수행한다. 모델 의견은 리뷰 자료이고, 재현한 위반은 커밋 차단 근거다. 모델 호출을 완료하지 못하면 결과에 미확인 사유를 표시하고 커밋을 보류한다.

모델을 사용하면 요청과 검토 대상의 코드 일부, 선택한 도구에서 얻은 근거가 모델 제공자에게 전송된다. `OPENAI_API_KEY`가 있으면 OpenAI API를 사용한다(기본 모델 `gpt-4.1-mini`). `AI_SLOP_MODEL`로 모델을 지정할 수 있다. API 키가 없으면 `codex login status`로 로그인을 확인한다. CLI 경로는 설치된 Codex의 비대화형 실행을 사용한다. [OpenAI 공식 문서](https://developers.openai.com/codex/noninteractive/)

## VS Code에서 보여줄 장면

게시글 작성 기능을 만드는 사용자가 코파일럿에 “제목이 비어 있으면 등록을 막아줘”라고 요청한다. 수정이 끝나면 같은 채팅에 `/slop 방금 고친 거, 스페이스만 넣어도 등록이 막혀?`라고 묻는다. 공백 입력을 놓친 버전에서는 Slop이 서버의 글 등록 코드를 직접 실행해서 글 생성을 시도했다는 반례를 보여준다. “그거 고쳐줘”를 보내면 같은 코파일럿이 그 결과를 받아 수정을 이어간다. 수정 뒤 같은 질문으로 다시 확인한다. 첫 수정부터 공백 입력이 막히면 실제 통과 결과를 보여준다.

## 시연하기

Git과 Python 3, Node.js가 필요하다. 검사는 index 안의 JavaScript를 실제 실행하므로 본인이 신뢰하는 로컬 시연 저장소에서 사용한다. 별도 DB 없이 컨트롤러를 호출하고 모델과 HTTP 요청/응답은 대역을 사용한다. 브라우저, 라우터 연결과 실제 저장 여부는 미확인으로 남긴다.

다음 명령은 **시연용 Conduit 복제본의 루트**에서 실행한다. 첫 줄은 팀 저장소의 실제 경로로 바꾼다.

```sh
SLOP_DIR=/absolute/path/to/my-copilot/ai-slop
export AI_SLOP_REQUEST="게시글 제목이 공백이면 등록을 막아줘"
python3 "$SLOP_DIR/gate.py"
python3 "$SLOP_DIR/gate.py" --request "게시글 제목이 공백이면 등록을 막아줘" --json
```

시연용 복제본에서만 다음처럼 훅을 연결한다. 기존 훅을 운용하는 저장소에서는 기존 pre-commit에서 gate.py를 호출하고 실패 코드를 전달한다. hooksPath 설정은 해당 복제본의 다른 Git 훅 경로도 바꾼다.

```sh
git config --local aiSlop.gate "$SLOP_DIR/gate.py"
git config --local core.hooksPath "$SLOP_DIR"
```

1. AI가 글 작성 화면만 수정했거나 서버에서 공백을 놓친 상태를 stage한다. 프론트엔드 변경에 임시 디버그 출력이 남아 있다면 줄 위치도 함께 뜬다.
2. 커밋이 차단되면 그 화면에 표시된 수정 요청을 코파일럿 채팅에 복사한다.
3. 수정 후 다시 stage하고 커밋한다. 같은 조건의 검사가 통과하면 Git이 커밋을 계속한다.

자동 훅은 지원하는 제품 코드 변경이 없으면 검사를 건너뛰고 커밋을 계속한다. 질문이나 `--request`로 직접 실행하면 검사 결과를 반환한다. 종료 코드 0은 검사 통과 또는 훅 대상 없음, 1은 위반, 2는 판정 불가다. 일부 검사가 실패하고 다른 검사가 미확인이면 전체는 실패이며 JSON에서 개별 상태를 확인할 수 있다. 도구 연동에는 `--json`을 사용한다. 종료 코드가 1이나 2일 때도 stdout에 결과가 있다.

## 리허설과 테스트

기준 앱은 TonyMckes/conduit-realworld-example-app의 커밋 `5e127d8`이다. 준비된 기준 앱의 로컬 경로를 넘기면 임시 복제본에서만 커밋 두 단계를 재현한다.

```sh
python3 ai-slop/rehearse.py /path/to/conduit
python3 -m unittest discover -s ai-slop -v
```

디버그 검사는 frontend/src의 제품 JS와 TS에서 새로 추가한 한 줄짜리 독립 console.log 또는 debugger 문장을 대상으로 한다. 일반 로그의 의도나 코드의 AI 작성 여부는 판단하지 않는다.

CLI와 훅 모두 기본으로 모델을 호출한다. 단위 테스트에서는 호출을 대역으로 바꾸며, 리허설은 실제 로그인이나 API 키가 필요하다. 기존 터미널 녹화는 모델 연결 전 버전이다.
