# AI Slop 검사와 연동 계약

## 검사가 증명하는 것

Conduit 시연에서 커밋할 코드에 새 디버그 문장이 남았는지, 글 생성 컨트롤러가 빈 제목과 공백 제목을 거부하면서 정상 제목을 처리하는지 확인한다. AI가 작성한 코드인지 판별하거나 코드 품질 전반에 점수를 매기는 기능은 현재 범위 밖이다.

| 검사 | 읽는 대상 | 근거 |
| --- | --- | --- |
| debug_traces | frontend/src 아래 제품 JS, JSX, TS 계열 파일에서 이번에 stage한 추가 줄 | 한 줄짜리 독립 console.log 또는 debugger에 해당하는 파일, 줄, 규칙 |
| article_title | stage한 Conduit 컨트롤러, 헬퍼, 오류 처리기 | 빈 문자열, 공백 세 칸, 정상 제목 각각의 응답 코드와 모델 생성 호출 횟수 |

컨트롤러는 Node에서 실행한다. 요청, 응답, ORM 모델에는 대역을 쓴다. 브라우저 조작, 실제 HTTP, PostgreSQL 저장 여부는 이 결과로 확인할 수 없다. 지원하지 않는 컨트롤러 구조나 실행 환경은 미확인으로 기록한다.

## 모델 검토

사용자 요청은 CLI의 `--request` 또는 환경변수 `AI_SLOP_REQUEST`로 전달한다. 생략하면 staged 변경을 전반적으로 검토하도록 요청한다. 확장 채팅의 대화 내역을 자동 수집하지 않는다.

첫 모델 응답은 검증 가설과 도구를 지정한다. Python이 허용된 도구와 인수인지 검사하고 같은 index에서 실행한다. 두 번째 응답에서 도구 근거를 바탕으로 수정 방향을 설명한다. JSON의 `agent` 필드에 가설, 도구, 근거와 피드백이 담긴다. 이 필드의 pass는 검토 절차가 끝났다는 뜻이다. 확인한 위반이나 실행 오류는 각각의 검사 상태에서 확인한다. 두 호출 중 하나가 실패하면 사유를 기록하며 모델 의견 없이 전체 pass를 반환하지 않는다.

## 작업 중 확인과 커밋 검사

위치 인자로 자연어 질문을 전달하거나 `--working`을 쓰면 임시 Git index에 현재 작업 파일의 추적된 변경을 반영해 모델과 검사기가 같은 스냅샷을 읽는다. 실제 index는 유지한다. 질문 없이 실행하는 기본 훅은 기존처럼 stage한 내용만 검사한다. 둘 다 같은 결과 구조를 사용한다.

## 호출과 판정

Git 훅은 커밋을 시도한 저장소에서 모델 검토를 포함한 gate.py를 실행한다. 별도 호출자는 `python3 gate.py --root <Conduit 저장소> --json`을 사용한다. 검사기는 index의 tree를 얻어 임시 index에서 두 검사를 실행하고, 결과를 반환하기 직전 원래 index가 같은지 확인한다. 다른 프로세스의 후속 Git 변경까지 잠그는 기능은 없다.

| 종료 코드 | status | 호출자가 할 일 |
| --- | --- | --- |
| 0 | skipped | 자동 훅에 검사 대상 변경이 없어 검사를 건너뛴 이유를 표시하고 커밋을 계속한다. |
| 0 | pass | 검사한 범위와 미확인 범위를 함께 표시하고 커밋을 계속한다. |
| 1 | fail | 커밋을 차단하고 실패한 입력, 기대값과 실제값, 문제 줄을 보여준다. |
| 2 | unchecked | 커밋을 보류하고 실행 환경 또는 index 변경을 확인한 뒤 다시 검사한다. |

정상적으로 검사를 수행하면 JSON에는 검사한 `tree`, 검사별 `checks`, 코드 위치를 담은 `findings`, 수정 요청 문장 목록 `feedback`, 확인하지 않은 범위 `untested`가 담긴다. 실행할 수 없을 때는 `status`와 `error`만 올 수 있다. 여러 검사 중 확정 실패가 있으면 실패를 우선 표시한다. 검사 중 index가 바뀌면 이전 tree의 결과로 커밋할 수 없다.

## 시연 연결 지점

훅 자체로 실패 표시, 커밋 차단, 수정 후 재검사를 시연할 수 있다. `--prompt`는 실행 시점의 index를 다시 검사하고 사람이 채팅에 복사할 요청을 출력한다. 통과한 개별 케이스는 생략하고 실패 조건과 미확인 범위를 보여준다. 종료 코드는 기본 출력과 같다. `--json`과 `--prompt` 중 하나를 고른다. 확장에서 실패 근거를 채팅에 전달하는 흐름은 #7과 #29에서 통합 확인할 대상이다. 코드 변경 영향도 표시와 PR 작성 화면은 각각의 담당 영역에서 확인한다. #30의 반복 규칙 초안 생성은 현재 검사 경로에 포함하지 않는다.
