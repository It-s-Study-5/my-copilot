1. 프로젝트 개요
함수 단위 코드 변경 영향도 분석 AI Agent
개발자가 수정하려는 함수에 커서를 놓고 단축키를 누르면, AI Agent가 해당 함수를 호출하는 다른 함수들을 계층적으로 추적하고 실제 코드 내용을 분석해 잠재적인 변경 영향 범위를 알려주는 기능.

개발 목적

기존 시스템을 수정할 때 개발자가 모든 호출 관계를 직접 추적하지 않아도, AI가 어떤 함수와 기능을 함께 확인해야 하는지 알려주는 거야.

프로젝트 전체를 새로 만드는 것이 아니라, 팀에서 개발 중인 OpenCode VS Code Extension에 추가할 기능 중 하나야.

2. 사용자 관점의 기능
기능 ① 커서 위치 기반 함수 선택
사용자는 함수명을 직접 입력하거나 함수 전체를 드래그하지 않아.
1. VS Code에서 분석할 파일을 연다.
2. 수정하려는 함수의 선언부부터 마지막 닫는 중괄호 사이에 커서를 놓는다.
3. 지정된 단축키를 누른다.
4. 영향도 분석이 자동으로 시작된다.

예를 들어 다음 코드의 어느 줄에 커서를 놓더라도 calculatePrice()를 분석하는 방식이야.

function calculatePrice(price, quantity) {
  const amount = price * quantity;
  return amount;
}


중첩 함수가 있다면 커서가 위치한 가장 안쪽 함수를 선택하고, 함수 밖이라면 오류를 안내하도록 했어.

별도의 자연어 질문이나 변경 예정 내용 입력은 필요 없어.

기능 ② 직접·간접 함수 호출 계층 탐색
선택한 함수를 호출하는 다른 함수들을 여러 단계에 걸쳐 찾아내는 기능이야.

calculatePrice()
사용자가 선택

preparePayment()
1단계 · 직접 호출자

createOrder()
2단계 · 간접 호출자

handleOrderRequest()
3단계 · 간접 호출자

화살표는 영향 범위를 거슬러 탐색하는 방향이며, 실제 함수 호출 방향은 반대야.
단순히 직접 호출하는 함수만 찾는 게 아니라, 그 함수를 다시 호출하는 상위 함수까지 추적해야 해.

또한 여러 파일에 걸친 호출 관계도 찾고, 각 호출 관계의 실제 파일과 코드 위치를 제공해야 해.

기능 ③ 연결된 함수의 실제 코드 분석
이게 이번 기능에서 특히 중요한 부분이야.

함수 호출 관계를 찾는 것만으로 분석을 끝내지 않아.

AI Agent가 연결된 함수의 실제 코드를 읽고, 선택한 함수의 결과를 어떻게 사용하는지 확인해야 해.

예를 들어 다음 코드가 있다고 해보자.
function createOrder(price, quantity) {
  const amount = calculatePrice(price, quantity);

  if (amount <= 0) {
    throw new Error("Invalid amount");
  }

  return saveOrder(amount);
}


Agent가 확인해야 할 내용은 다음과 같아.
- calculatePrice()의 반환값을 amount에 저장한다.
- amount를 조건문에서 검사한다.
- amount를 saveOrder()에 전달한다.
- 따라서 계산 결과의 타입이나 값이 바뀌면 조건 검사와 저장 함수의 입력을 검토할 필요가 있다.

단순히 createOrder()가 calculatePrice()를 호출한다는 사실보다 그 결과를 실제로 어떻게 사용하는지가 중요해.

기능 ④ AI 기반 잠재적 변경 영향 분석
AI Agent는 호출 계층과 실제 함수 내용을 바탕으로 변경 영향 가능성을 설명해.

변경하려는 내용을 사용자가 알려주지 않아도 다음과 같은 분석을 수행하는 게 목표야.

AI 영향도 분석 결과 예시

분석 대상: calculatePrice()

preparePayment()

계산 결과를 그대로 반환하므로 반환값의 타입이나 계산 방식이 변경될 경우 전달 결과가 달라질 수 있습니다.

createOrder()

계산 결과를 금액 유효성 검사에 사용하므로 반환값의 범위·타입이 변경되면 조건문 동작을 확인해야 합니다.

handleOrderRequest()

주문 처리 결과를 상위 응답에 전달하므로 간접적인 영향 가능성이 있습니다.

여기서 핵심은 실제로 확인된 코드 관계와 AI가 추정한 위험을 구분하는 거야.

변경 내용이 없기 때문에 특정 오류가 반드시 발생한다고 판단하면 안 돼.

기능 ⑤ 결과 요약 및 상세 근거 제공
결과를 처음부터 복잡하게 전부 보여주는 방식은 선택하지 않았어.

우리가 정한 방식은 주요 영향 함수와 AI 요약을 먼저 보여주고, 자세한 분석 결과는 펼쳐서 확인하는 방식이야.

3. AI Agent 내부 기능
최종적으로 네 Agent에 필요한 구성은 다음과 같아.
구성	담당 기능
Function Resolver	커서 위치로 함수 식별
Call Hierarchy Analyzer	직접·간접 호출 계층 탐색
Code Context Reader	관련 함수의 실제 소스코드 수집
Usage Inspector	함수 인자 및 반환값 사용 방식 확인
Agent Orchestrator	분석 도구 호출, 필요 시 추가 탐색
Model Adapter	선택한 AI 모델 연결
Result Formatter	요약·상세 JSON 반환

중요한 점은 정적 코드 분석과 AI의 역할을 분리하는 것이야.

정적 분석기는 호출 관계와 코드 근거를 찾고, AI Agent는 관련 함수를 추가로 살펴보며 잠재적 영향을 설명해.
